- **`help(Obj)` shows every class doc the `.pyi` shows, and a view runs its constructor's `init_post_parse` (gh-2401).** The runtime class docstring rendered the full block only for a hand-written list of reasons (a summary, a `Raises`, a `Warns`, enum choices), so a documented constructor parameter (`[[<obj>.init_params]] doc`) or state field (`[[<obj>.state]] doc`) reached the stub and not `__doc__`, on a standalone object, a module object, a view and under `jm bind`; a module object's state doc reached neither, because the replayed manifest dropped it. One predicate now decides every runtime class docstring by asking the class-docstring builder whether anything authored changes it, and `apply`'s refresh of a sacred fragment's `tp_doc` reads that same answer, so an edited parameter doc no longer leaves the old text behind. A view that inherits its parent's `init_params` now runs the parent's `init_post_parse`; one that declares its own runs only the `init_post_parse` it declares on its `[[<obj>.views]]` row, which the replay keeps.
