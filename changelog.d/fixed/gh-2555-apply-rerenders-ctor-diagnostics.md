- **`jm apply` re-renders a module constructor whose `create_error` or warnings changed in the manifest (gh-2555).** A module object's or a view's binding fragment is kept by `apply`, and its `tp_init` with it. So editing `create_error`, `create_error_message`, `create_why` or a `[[<obj>.warnings]]` entry in the manifest updated the `.pyi` while the built class went on raising the old exception and emitting the old warning, `help()` kept the old `Raises` and `Warns` text, and `jm status --check` passed. `apply` now re-renders a constructor and class docstring that are jm's own render apart from those diagnostics, and names each one it rewrites. A constructor edited anywhere else is left alone, and `apply` warns about it. `status --check` now fails on it in a new `DIAGNOSTICS` section. A standalone object was never affected: `apply` regenerates its whole `_ext.c`.
