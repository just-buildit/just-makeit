- **A module's collocated object keeps what the module's core held (gh-2843).** `jm object m --module m` rendered the object's `m_core.h` and `m_core.c` over the module's own. A module function declared before the object lost its declaration, so `m_ext.c` called a function nothing declared and `jm status --check` reported the header STALE on a tree the verb had just written; and any function you had written into `m_core.c` was gone with no prompt. The header is now the object's render plus every declaration, inline definition and `#include` the module's header held, and `m_core.c` is only appended to: the object's definitions it lacks are added, and nothing you wrote is touched. Code jm cannot place in the new header, such as a macro, is refused with the file named, and the tree is left as it was: move it to a header of your own and include that.
