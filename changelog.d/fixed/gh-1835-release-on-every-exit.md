- **A refused argument releases everything the binding already holds (gh-1835, gh-2689).** A binding that takes several arguments acquires them one after another -- a `path` the parse converts, then each array -- and each early return owes a release of what is held at that point; every emitter spelled that debt for itself and got it wrong somewhere. An `optional` array init-param, refused, leaked every array acquired before it (one reference per bad call); a module function's array refusal released only the paths declared BEFORE it, so `(x: float[], p: path, y: float[])` leaked `p` when `x` was refused; and a method released no path on ANY refusal -- an array, an enum, a capsule. A module function with an array before an enum did not compile (`'x_arr' undeclared`: the enum's refusal named an array the conversion runs ahead of). Every site now asks one emitter, `_coerce.held_release` (the arrays held, then every path), and the parse-time exits ask it for the paths alone; a multi-statement failure no longer sits under the capsule unwrap's brace-less `if`. Part of gh-2355: a module function's capsule param was a second copy of the unwrap that raised the raw `AttributeError` of the `._capsule` lookup; it now calls `capsule_unwrap_c`, the method face's emitter, and raises the same `TypeError` naming the capsule wanted. `tests/test_gh1835_release_on_every_exit.py` builds all fourteen shapes and compares the array's and the path's reference counts after 100 refusals each.
