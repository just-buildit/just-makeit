- **A composer source that generates no longer renders a stale value after a field is set (gh-2758).** `s = Synth(type="tone", freq=1e3); s.steps(64); s.freq = 2e3; s.steps(64)` kept rendering 1 kHz while `s.freq` read `2e3`: the generator `steps()` builds lazily from the source was cached in `self->_gen`, and only a re-`__init__` and the `bytes` / complex / owned-pointer setters dropped it. Every other writer -- each plain, enum, `ranged` and `check_fn` field setter, a `set_fn` write, and the `fs` setter -- now converts the value, waits for a `steps()` running on another thread, writes, and drops the generator through the one `_gen_drop_c` that `__init__` and the buffer setters share, so the next `steps()` builds from the new value. A refused `set_fn` writes nothing and keeps its generator. Assigning restarts the generator (as `__init__` does); `reset()` still rewinds without rebuilding, and the `steps()` docstring and the object-of-objects page say so.
