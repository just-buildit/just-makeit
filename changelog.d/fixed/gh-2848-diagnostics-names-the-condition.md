- **A DIAGNOSTICS report for a warning whose condition changed names the condition (gh-2848).** When only a warning's `condition` differed from the manifest's, `apply` and `status` showed the same class and message on both sides and claimed the constructor was not jm's own render, though nothing was hand-edited. Each side now reads `... under self->handle->hot`, and the detail gives the reason: the kept warning's condition is not one the manifest renders. The decision is unchanged: a condition is the author's C as often as a field, jm cannot tell a manifest edit from an author's by reading it, so it reports rather than re-renders, and re-running `jm warning ... --condition` hands the block back to jm.
