- **Removing a module's collocated object leaves the module its core (gh-2141).** `jm remove object filt` on the object named for its module (`jm module filt && jm object filt --module filt`) deleted the module's own `native/src/filt/` and `native/inc/<pkg>/filt/` whole, then wrote the module's CMakeLists and `_ext.c` back into the emptied directory: `jm status --check` reported `filt_core.h` and `filt_core.c` MISSING and cmake could not configure. Those directories and that core are the module's, so the removal now takes only what is the object's own (its binding fragment, its tests and benches) and leaves the core, with your C in it, for the module to build. It prints a note that the object's declarations and bodies in the core are yours to delete. The C test and bench stay too while the module has functions, since they are the module core's.
