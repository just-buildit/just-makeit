- **Two objects' `single = true` results can share one declared record (gh-2889).** A `--single` method or module function whose `--return-type` struct is declared with `jm record` now takes its columns from that declaration, whichever component declares it. Until now each method carried its own `result_fields`, so a struct returned by two objects (doppler's receiver `status()` and its pool's) was described twice, and a field added to one copy reached neither the other binding nor its `.pyi`. One `jm record` edit now reaches every binding, stub, record registration and contract test that returns the struct, a module function in a module whose objects never name the struct included, and `jm script`, `apply` and `status` agree. A struct declared by two components is refused, as is a `--result-field` that restates a declared struct's columns. Removing the declaring object or module is refused while a member elsewhere returns the struct, naming each member's `jm remove`. Each binding keeps its own Python type name. A module object whose shared-record wrapper was re-rendered no longer keeps the old body, which had filled the old columns and left the new field `<NULL>` at runtime.
