- **A failed `jm new` whose cleanup cannot finish still reports its own error (gh-2828).** If a symlink to a directory appeared where `jm new` had made its project's outermost directory, the rollback's `shutil.rmtree` raised `OSError: Cannot call rmtree on a symbolic link` from the guard's `finally`, and that replaced the refusal or failure that actually stopped the command with an `OSError` traceback. `_undo` now removes such a link without following it, and any `OSError` from a rollback prints one line naming the path it left behind (`could not remove <path>: ...; it is left behind.`) and lets the command's own error leave.
