- **`jm apply` rewrites a module constructor's create-failure block when the manifest's `create_error` or `create_error_message` changes (gh-2555).** The constructor wrapper of a module object is jm's render with no author placeholder, but `apply` kept its body from the sacred fragment, so the binding went on raising the old exception while the `.pyi` moved on, and `jm status --check` passed. The wrapper is now jm-owned, and the class docstring's `Raises` section, which has no authoring path, is refreshed too. An author's own functions in the same fragment are kept as before.
